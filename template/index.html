What IQ-Server is

Doing one thing is what makes it fast.

IQ is a streaming server specialized in a single task: relaying LLM output from application backends to browsers.

  1. 01

    Publish

    Your backend sends each chunk of model output to IQ as it arrives, over a plain HTTP request, from any language.

  2. 02

    Fan out

    IQ fans it out to the browsers watching that answer over Server-Sent Events, the standard the browser already knows. The built-in EventSource is the whole client.

  3. 03

    Hold

    While the answer is being generated, IQ keeps it in memory, so any browser that reconnects resumes exactly where it left off.

  4. 04

    Let go

    When the answer ends, IQ lets it go. Your backend already has the result. IQ carries it only while it is being written.

Stream replay

The connection will drop. The answer won’t.

Mobile users change networks. Laptops sleep. Corporate proxies cut idle connections. On a ten-second answer, some of your users will lose their connection mid-stream every day.

With IQ, the browser simply reconnects, and IQ replays exactly the tokens it missed, then continues live. No gaps, no repeats, nothing for your frontend or backend to rebuild. The browser’s standard EventSource does it on its own: it reconnects and tells IQ the last event it received.

0 Events lost on reconnect

In the benchmark, one browser in ten lost its connection mid-answer. Every one of them came back to every event it had missed: 0 events lost, at every load level, on one CPU and on two.

Why it matters for AI products

What replay saves you.

LLM spend

No more paying twice for the same answer.

When a stream breaks, users retry, and every retry is another full LLM generation billed by your provider. With replay, the answer they were already paying for simply continues.

Code

No reconnection logic to build.

No buffering tokens in Redis, no “resume from offset” endpoints, no client-side state machines.

Support

Fewer support tickets about “the AI stopped mid-sentence”.

A complete contract for every answer.

Replay is only half of it. IQ also guarantees that every browser learns how the answer ended, even one that reconnects too late.

Every event, in order, exactly once.

All browsers watching an answer see the same events in the same order.

A clear ending.

Each browser receives a final signal: the answer finished, or it failed and why.

An honest “it’s over”.

A browser that comes back after the answer ended is told so right away, and loads the final result from your backend, instead of hanging or showing half an answer.

Slow devices never slow down others.

Each browser is served at its own pace. A slow phone never holds back the other viewers, and is never dropped for being slow.

Connections stay alive while the model thinks.

Regular heartbeats keep proxies and load balancers from closing a stream while an agent waits on a tool.

Specialized, not general purpose

Why general-purpose servers can’t do this at streaming speed.

Server When a browser reconnects mid-answer
IQ-Server Resumes from the exact event it missed, from memory, at full speed: 42,000 events/s on one CPU.
Mercure, Soketi, Laravel Reverb (default) Keep nothing. The browser loses everything sent while it was away: 45 to 56 events of a 429-event run in the benchmark, the middle of the answer.
Mercure with history Can resume, but writes every event to a database file before relaying it. It never passed 780 events per second, and at just 100 concurrent runs its p99 latency was 20 seconds.
General-purpose servers make you choose: speed without replay, or replay without speed.

IQ keeps every running answer in memory, for as long as it is being written and no longer, so replay costs nothing on the hot path: no disk, no database, no broker. That is how it resumes a browser within milliseconds of reconnecting while relaying tens of thousands of events per second.

One endpoint for any language

One endpoint. Any language.

If your backend can make an HTTP request, it can stream through IQ. Publishing is a plain HTTP request with one JSON line per event.

PHP Python Node.js Go Ruby Java .NET anything that speaks HTTP

  • No SDK required in the browser.

    Standard Server-Sent Events, read by the browser’s built-in EventSource.

  • Any front-end protocol.

    AG-UI, the Vercel AI SDK, plain text or your own format: IQ relays your events exactly as you send them. It never reads or changes what you send.

  • Any model, any provider.

    IQ sits after the model, so it works with every LLM, hosted or self-hosted.

  • Simple, secure tokens.

    Your backend signs short-lived tokens with a few lines of code, in any language: one to publish, one to watch. A watch token can never be used to publish.

  • One Docker image.

    For amd64 and arm64. No database, no Redis, no disk and no message broker: everything happens in memory.
