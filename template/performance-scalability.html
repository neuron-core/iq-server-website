The test

The exact traffic an AI product generates.

Simulated agent runs, each made of 429 AG-UI events over about 10 seconds. Each run has a streamed text answer, a tool call with streamed arguments, a 1.5-second pause while the tool runs, an 8 KB tool result, and a second answer, with runs starting and ending all the time and one browser in ten losing its connection mid-answer.

Each server ran alone, on the same CPU and memory, in its fastest configuration.

Scalability

From one CPU to every CPU of the machine.

IQ runs as a single process on one CPU, or as a cluster that uses every CPU of the machine: one worker per CPU, with a lightweight router in front. Each answer lives on one worker, so its tokens go straight from your backend to your users’ browsers, never crossing processes and never passing through a broker.

Memory

Light on memory.

A whole agent run, kept in full so any browser can resume it, costs IQ about 80–95 KiB. A 2 GB container holds about 1,400 complete 4,000-token answers in flight at once. IQ sizes itself from its container’s memory limit and refuses new work before it runs out, so a traffic spike never crashes the process and the answers already running.

Specialization vs general purpose

Every AI product streams. The streaming layer was built for something else.

Chat assistants, copilots, agents and AI search all send their answers word by word. But WebSocket hubs, pub/sub brokers and notification servers were designed to deliver a chat message or a notification now and then.

An LLM answer is not like that. It is hundreds of small events, a few dozen milliseconds apart, for ten seconds or more, with pauses while a tool runs and the occasional large payload, for every user at once.

Put that traffic through a general-purpose server and three things happen:

01 · CPU

It runs out of CPU long before you expect.

Every token pays the full price of a message built for a different job.

02 · Latency

Latency piles up.

Once the server falls behind, tokens arrive in bursts, seconds late, and the “typing” effect your users expect falls apart.

03 · Reconnects

Dropped connections lose tokens.

The browser reconnects and the middle of the answer is gone. The user sees a broken answer, retries, and you pay the LLM provider to generate it again.

Doing one thing is what makes it fast.

IQ was built to remove all three. It keeps every running answer in memory, for as long as it is being written and no longer, so replay costs nothing on the hot path. Just the shortest possible path from your model to your user’s screen.

Benchmark

How we measured.

The figures on this page come from IQ’s reproducible benchmark suite, which runs with Docker alone. It streams simulated AG-UI agent runs through each server, one at a time, on the same CPU and memory limits, and measures the events delivered, the CPU and memory used, the latency each event saw from the moment the model produced it, and the events browsers lost when their connection dropped.

Each competitor ran in its fastest documented setup: Mercure with its in-memory transport, and again with its default transport that keeps history; Laravel Reverb with its recommended event loop and production settings; Soketi with its official image; Reverb and Soketi scaled out with Redis on two CPUs, as their documentation describes. Every server checked that each browser was allowed to read the stream it asked for.

The results were measured on a single machine (Intel Core Ultra 7 155H). Absolute numbers depend on the hardware: compare servers within one run, on one machine.
